# กลอง → MIDI

เว็บแอปถอดจังหวะกลองจากไฟล์เสียงออกมาเป็นโน้ตและไฟล์ MIDI แก้บนกริด ฟังเทียบ แล้วส่งออก

**ที่อยู่เว็บแอป:** https://potagomo.github.io/T/

ทุกอย่างทำงานในเครื่องของผู้ใช้ทั้งหมด ไฟล์เสียงและงานที่บันทึกไม่เคยถูกส่งขึ้นเซิร์ฟเวอร์

---

## 1. เปิดใช้ GitHub Pages (ทำครั้งเดียว)

ไปที่ **Settings → Pages** ของ repo นี้ แล้วเลือกอย่างใดอย่างหนึ่ง

**แบบที่แนะนำ — GitHub Actions (ไม่ต้องตั้งอะไรเลย)**

* workflow เปิด Pages ให้เองตั้งแต่ deploy ครั้งแรก (`enablement: true`)
  ปกติจึงไม่ต้องเข้าไปกดอะไรที่หน้า Settings
* ทุกครั้งที่ push จะ deploy ให้เองด้วย `.github/workflows/pages.yml`
  ซึ่งจะประทับเลข commit ลงใน `sw.js` และตรวจว่าไฟล์ที่จำเป็นครบก่อนเผยแพร่
* ถ้า workflow ฟ้องว่าเปิด Pages ไม่ได้ (บางบัญชี/บาง org ปิดสิทธิ์นี้ไว้)
  ค่อยไปตั้งเองที่ Settings → Pages → Source = **GitHub Actions** แล้วสั่ง re-run

**แบบง่าย — Deploy from a branch**

* Source = **Deploy from a branch**
* Branch = `claude/web-app-html-file-bicwtc` (หรือ `main`) · Folder = **/ (root)**
* ใช้ได้เหมือนกัน แค่ไม่มีขั้นตอนตรวจไฟล์ให้

รอประมาณ 1–2 นาทีแล้วเปิด https://potagomo.github.io/T/

> ระหว่างที่ยังไม่เปิด Pages ลิงก์จะขึ้น 404 เป็นเรื่องปกติ

## 2. ติดตั้งลงหน้าโฮม

ทำแล้วจะได้ไอคอนเหมือนแอปจริง เปิดเต็มจอไม่มีแถบที่อยู่ของเบราว์เซอร์ และ
**ข้อมูลที่บันทึกไว้จะอยู่ทนกว่าการเปิดในแท็บเบราว์เซอร์ธรรมดามาก**

| เครื่อง | วิธีทำ |
|---|---|
| **iPad / iPhone** | เปิดลิงก์ด้วย **Safari** (Chrome บน iOS ทำไม่ได้) → ปุ่มแชร์ <kbd>􀈂</kbd> → **เพิ่มไปยังหน้าจอโฮม** |
| **Android** | เปิดด้วย Chrome → เมนู ⋮ → **ติดตั้งแอป** / **เพิ่มลงในหน้าจอหลัก** |
| **Mac / Windows** | Chrome หรือ Edge → ไอคอนติดตั้งที่ท้ายแถบที่อยู่ |

เปิดครั้งแรกหนึ่งครั้งตอนมีเน็ต หลังจากนั้น **ใช้ได้แม้ไม่มีเน็ตเลย**

## 3. งานที่บันทึกเก็บอยู่ที่ไหน — อ่านตรงนี้ก่อน

งานเก็บอยู่ใน `localStorage` ของเบราว์เซอร์ **บนเครื่องนั้นเครื่องเดียว**
ไม่ได้ซิงก์ข้ามเครื่อง และไม่มีสำเนาอยู่บนเซิร์ฟเวอร์

**สามข้อที่ต้องรู้**

1. **ของเดิมที่เคยทำไว้ตอนเปิดจากไฟล์ในเครื่อง จะไม่ตามมาเอง**
   เพราะเบราว์เซอร์มองว่า `file://` กับ `https://` เป็นคนละที่เก็บ
   ให้เปิดไฟล์เดิม → กด **ดาวน์โหลดไฟล์สำรอง (.klong)** → เปิดเว็บแอป → **นำเข้าไฟล์สำรอง**

2. **iOS ล้างข้อมูลเว็บทิ้งได้เอง** ถ้าไม่ได้เปิดแอปนานหลายสัปดาห์
   การติดตั้งลงหน้าโฮมช่วยได้มาก แต่ไม่รับประกัน

3. เพราะสองข้อบน → **ไฟล์สำรอง `.klong` คือของจริง** จุดบันทึกในเครื่องเป็นแค่ความสะดวก
   งานไหนสำคัญ ดาวน์โหลด `.klong` เก็บไว้ใน iCloud Drive หรือ Google Drive ด้วย

## 4. เรื่องความปลอดภัย

**ที่ทำให้แล้ว**

* **HTTPS** ทุกการเชื่อมต่อ GitHub Pages บังคับให้อยู่แล้ว
* **ไม่ต่อออกไปไหนเลย** ไม่มี CDN ไม่มีตัวเก็บสถิติ ไม่มีโฆษณา
  ฟอนต์ IBM Plex Sans Thai ถูกย้ายมาเก็บไว้ในโปรเจกต์เอง (สัญญาอนุญาต SIL OFL 1.1)
  จึงไม่มีการเรียก Google Fonts อีกแล้ว — ทั้งเร็วขึ้น เปิดออฟไลน์ได้ และไม่มีใครนอกเครื่องรู้ว่าเราเปิดหน้านี้
* **Content-Security-Policy** ล็อกไว้ว่าหน้านี้โหลดโค้ด รูป ฟอนต์ และเสียงได้จากตัวเองเท่านั้น
  ต่อให้มีใครแทรกลิงก์แปลกปลอมเข้ามา เบราว์เซอร์ก็จะไม่ยอมโหลด
* **กันการเอาหน้านี้ไปฝังใน iframe ของเว็บอื่น** (clickjacking)
* **สั่งไม่ให้เสิร์ชเอนจินเก็บไปทำดัชนี** ด้วย `<meta name="robots" content="noindex">`

**ที่ต้องรู้ไว้**

* repo นี้เป็น **public** ฉะนั้น **ใครที่รู้ลิงก์ก็เปิดเว็บแอปได้** ตัวโปรแกรมเป็นสาธารณะ
* แต่ **งานของแต่ละคนอยู่แค่ในเครื่องของคนนั้น** คนอื่นเปิดลิงก์เดียวกันจะเห็นกริดเปล่า
  ไม่มีทางเห็นงานของเรา เพราะไม่มีอะไรถูกส่งขึ้นไปเก็บไว้ตรงกลางเลย
* ถ้าอยากไม่ให้คนนอกเปิดเว็บแอปได้เลยจริง ๆ GitHub Pages แบบฟรีทำไม่ได้
  ต้องใช้ Cloudflare Access วางหน้าไว้ หรือเปลี่ยนไปใช้ GitHub Pages ของ repo private (ต้องมีแพ็กเกจเสียเงิน)
* `'unsafe-eval'` ใน CSP จำเป็นจริง ๆ เพราะตัวโปรแกรมถูกเก็บเป็นข้อความแล้วรันด้วย `new Function()`
  ซึ่งเป็นกลไกของฟีเจอร์ "ไฟล์ล็อก" ที่มีมาแต่เดิม ไม่ได้เพิ่งใส่เพิ่ม

## 5. ฟรีตลอดไปแค่ไหน

GitHub Pages สำหรับ repo สาธารณะ **ฟรี ไม่มีวันหมดอายุ ไม่ต้องผูกบัตร**
ไม่มีการ "หลับ" แบบบริการโฮสต์ฟรีเจ้าอื่น และไม่มีโควตาที่ใช้แล้วหมด

ขีดจำกัดที่ GitHub ประกาศไว้ — ของเราอยู่ห่างมาก

| รายการ | ขีดจำกัด | โปรเจกต์นี้ใช้ |
|---|---|---|
| ขนาดเว็บ | 1 GB | ~0.4 MB |
| ปริมาณโหลดต่อเดือน | 100 GB | ไม่ถึง แม้เปิดวันละหลายร้อยครั้ง |
| จำนวน build ต่อชั่วโมง | 10 | เท่าจำนวนครั้งที่ push |

แถมยังเป็นเว็บนิ่ง (static) ล้วน ไม่มีเซิร์ฟเวอร์ ไม่มีฐานข้อมูล ไม่มี dependency
ที่ต้องคอยอัปเดตตามช่องโหว่ จึงไม่มีอะไรพังเองตามเวลา
และถึงวันหนึ่งอยากย้ายไปโฮสต์ที่อื่น ก็แค่ก๊อบไฟล์ทั้งโฟลเดอร์ไปวาง ใช้ได้ทันที

## 6. อัปเดตตัวโปรแกรม

แก้ `index.html` แล้ว push ขึ้น branch ที่ตั้ง Pages ไว้ เท่านั้นเอง

ฝั่งผู้ใช้จะไม่ถูกรีโหลดกลางคัน — พอมีรุ่นใหม่จะมี **แถบขึ้นข้างบนให้กดอัปเดตเอง**
ตั้งใจทำแบบนี้เพราะถ้ารีโหลดเองอัตโนมัติ งานที่กำลังแก้อยู่บนกริดจะหายไป

---

## 7. ไฟล์ในโปรเจกต์

```
index.html                 ตัวโปรแกรมทั้งหมด (ไฟล์เดียวจบ)
manifest.webmanifest       ข้อมูลสำหรับติดตั้งลงหน้าโฮม
sw.js                      Service Worker — ทำให้ใช้ได้ตอนไม่มีเน็ต
404.html                   หน้าที่ขึ้นเมื่อเปิดที่อยู่ผิด
fonts/                     IBM Plex Sans Thai (ไทย + ละติน, 12 ไฟล์ ~100 KB)
icons/                     ไอคอนแอปสำหรับหน้าโฮมและแท็บเบราว์เซอร์
.nojekyll                  บอก GitHub Pages ว่าไม่ต้องเอา Jekyll มาประมวลผล
.github/workflows/pages.yml  deploy อัตโนมัติเมื่อ push
```

`index.html` ถูกคอมมิตครั้งแรกแบบยังไม่แก้อะไรเลย แล้วค่อยเพิ่มชั้นเว็บแอปในคอมมิตถัดมา
จึงดู `git log -p index.html` แล้วเห็นได้ชัดว่าแตะอะไรไปบ้าง — ตรรกะของโปรแกรมไม่ถูกแก้เลยสักบรรทัด

## 8. ทดสอบอะไรไปแล้วบ้าง

รันจริงบน Chromium ทั้งขนาดจอ iPad Pro 11" และ iPhone 13 ผ่านทุกข้อ

* โปรแกรมเปิดขึ้นและวาดกริดได้ทั้งสองขนาดจอ
* แตะนิ้ววางโน้ตบนกริดได้ แล้วส่งออกได้จริงทั้ง `.mid` (ขึ้นต้นด้วย `MThd` ถูกต้อง) และ `.musicxml`
* กดเล่นแล้วหัวอ่านเดินและมีเสียงออก (AudioContext ทำงาน)
* **ตัดเน็ตแล้วโหลดใหม่ ยังเปิดใช้ได้ครบ ฟอนต์มาครบ**
* ไม่มีคำขอออกไปนอกเครื่องแม้แต่รายการเดียว
* ไม่มี CSP violation และไม่มี error ใน console
* บันทึก/อ่าน/ลบจุดบันทึกในเครื่องทำงานปกติ
* แถบแจ้งรุ่นใหม่ไม่ขึ้นตอนเปิดครั้งแรก ขึ้นเมื่อมีรุ่นใหม่จริง และกดแล้วอัปเดตเรียบร้อย
