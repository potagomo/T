# กลอง → MIDI

เว็บแอปถอดจังหวะกลองจากไฟล์เสียงออกมาเป็นโน้ตและไฟล์ MIDI แก้บนกริด ฟังเทียบ แล้วส่งออก

**ที่อยู่เว็บแอป:** https://potagomo.github.io/T/

ทุกอย่างทำงานในเครื่องของผู้ใช้ทั้งหมด ไฟล์เสียงและงานที่บันทึกไม่เคยถูกส่งขึ้นเซิร์ฟเวอร์

## แอปที่สอง: ครูต้า — บันทึกการสอนกลอง

**ที่อยู่:** https://potagomo.github.io/T/lesson/

แอปแยกขาดจากกลอง → MIDI ทั้งไอคอน ข้อมูล และ Service Worker ติดตั้งลงหน้าโฮมได้คนละไอคอน

**ติดตั้ง** — iPad: เปิดด้วย Safari → แชร์ → เพิ่มไปยังหน้าจอโฮม ·
Samsung S26 Ultra: เปิดด้วย Chrome หรือ Samsung Internet → ⋮ → ติดตั้งแอป

**ซิงค์เรียลไทม์ iPad ↔ มือถือ** ใช้ Firebase ของคุณเอง (ฟรี ไม่ต้องผูกบัตร ข้อมูลเป็นของคุณคนเดียว)

1. เครื่องแรก: ในแอปเปิด ⚙ → ☁ ซิงค์ข้ามเครื่อง แล้วทำตามขั้นตอนที่แอปบอก
   (สร้างโปรเจกต์ที่ console.firebase.google.com · เปิด Email/Password · สร้าง Firestore · วางกฎ · วาง firebaseConfig)
   จากนั้น **สร้างบัญชีใหม่** ด้วยอีเมล + รหัสผ่าน
2. เครื่องที่สอง: วาง **รหัสตั้งค่า `KRUTA1:…`** ที่ก๊อบจากเครื่องแรก → **เข้าสู่ระบบ** ด้วยบัญชีเดียวกัน
   → แอปจะถามว่ารวมข้อมูลหรือใช้ของบนคลาวด์ (ถ้าเครื่องนี้มีแต่ข้อมูลตัวอย่าง เลือก "ใช้ของบนคลาวด์")

หลังจากนั้นบันทึกบนเครื่องไหน อีกเครื่องเห็นภายในไม่กี่วินาที แก้/ลบก็ตามไปด้วย
ไม่มีเน็ตก็บันทึกได้ตามปกติ พอเน็ตกลับมาจะส่งขึ้นเอง

**ขีดจำกัดของ Firebase แบบฟรี** (ใช้คนเดียวห่างจากเพดานมาก):
อ่าน 50,000 / เขียน 20,000 ครั้งต่อวัน · พื้นที่ 1 GB — ตัวที่จะชนก่อนคือ **รูปและคลิป**
ถ้าแนบคลิปเยอะ ให้แปะเป็นลิงก์ Google Drive/YouTube แทน (แอปมีช่องให้แล้ว) หรือปิดซิงค์รูป/คลิปในหน้าซิงค์

**ล็อกหน้าจอ** — รหัสผ่านเข้าแอปและรหัสกู้คืนเก็บแบบ PBKDF2-SHA256 600,000 รอบ + salt สุ่ม
(WebCrypto ของเบราว์เซอร์ ไม่มีไลบรารีนอก) แทนแฮช 32 บิตของเดิม รหัสเดิมยังเข้าได้และถูกอัปเกรดให้เองตอนเข้าครั้งแรก
โค้ดอยู่ที่ `tools/lesson-layer/10-secure-lock.js`

**ปลดล็อกเร็ว** — รหัสเป็นตัวเลขล้วน หน้าล็อกโชว์แป้น 0–9 ปุ่มใหญ่แทนแป้นพิมพ์ของเครื่อง (สลับกลับได้) ·
⚙ › ความปลอดภัย › 👆 ปลดล็อกด้วยลายนิ้วมือ (iPad: Face ID / Touch ID) ใช้ WebAuthn/พาสคีย์ของเครื่อง ตั้งทีละเครื่อง
แอปเก็บแค่กุญแจสาธารณะ และตรวจ challenge · origin · ธงยืนยันตัวตน · ลายเซ็น ก่อนเข้าแอป · มือถือ Android ถามลายนิ้วมือเองตอนเปิดแอป
iPad ต้องแตะปุ่มก่อน (Safari บังคับ) · โค้ดอยู่ที่ `tools/lesson-layer/15-quick-unlock.js` · ตรวจ: `node tools/test-quick-unlock.js`

**คลิปวิดีโอของคาบ** — ช่อง "คลิป / รูปของคาบนี้" แนบวิดีโอได้ (ไม่เกิน 10 นาที · เกิน 5 นาทีเตือนว่า LINE อาจไม่ยอมส่ง)
หน้าปกเป็นเฟรมจากคลิป + ปุ่ม ▶ + ความยาว · แตะหน้าปกเล่นในแอป · การ์ดส่งผู้ปกครองมีปุ่ม 🎬 ส่งคลิปวิดีโอ
ซึ่งส่ง **ตัวไฟล์** ไป LINE ผ่านเมนูแชร์ของเครื่อง ผู้ปกครองกดเล่นในแชตได้เลย ไม่ต้องสมัครอะไร
ปุ่มหลัก **↗ แชร์รูป + คลิปไป LINE** ส่งรูปการ์ดและคลิปในการแชร์ครั้งเดียว (Chrome ส่งเป็นชนิด `*/*` รวมไม่เกิน 50 MB
— คลิปใหญ่ถูกย่อก่อน) · เครื่องที่ไม่รับไฟล์ปนกันส่งรูปก่อนแล้วมีปุ่ม "ส่งคลิปต่อ" · ยังมี "ส่งเฉพาะคลิป" สำรอง
ตัวคลิปเก็บในเครื่องที่แนบเท่านั้น (ไม่ซิงค์ ไม่เข้าไฟล์สำรอง — กันโควตา Firestore ฟรีเต็ม) หน้าปกซิงค์ตามปกติ
Chrome แชร์ไฟล์ได้ไม่เกิน 50 MB คลิปที่ใหญ่กว่า 48 MB จึงถูกย่อในเครื่องเป็น MP4 720p (H.264, เสียงเดิม) ด้วย WebCodecs
ผ่าน `lesson/vendor/mediabunny-1.59.1.js` (MPL-2.0) · ภาพในการ์ดรายงานไม่มีปุ่ม ▶ (มีเฉพาะภาพย่อในแอปที่แตะเล่นได้)
หน้าส่งผู้ปกครองมีช่องติ๊ก **🖼 ใส่ภาพหน้าปกคลิปในรูป** — ปิดแล้วรูปการ์ดไม่มีภาพหน้าปก (คลิปยังส่งได้ตามเดิม)
จำแยกทีละคาบ และใช้เป็นค่าเริ่มต้นของคาบถัดไป · หน้าปกเลือกเฟรมที่มีภาพจริง (ข้ามเฟรมดำช่วงต้นคลิป)
หน้าปกเก่าที่ดำถูกสร้างใหม่เองตอนเปิดแอปบนเครื่องที่มีคลิป

**🎯 งานสำคัญ (นับถอยหลัง)** — คอนเสิร์ต สอบ แข่งขัน: ตั้งชื่อ ไอคอน วัน เวลา สถานที่ (แท็บภาพรวม › + เพิ่มงานสำคัญ หรือ ⚙ › การสอน)
นับถอยหลังยิ่งใกล้ยิ่งละเอียด: ตัวเลขใหญ่ = 2 หน่วยแรกที่ไม่เป็นศูนย์ (เดือน+สัปดาห์ › สัปดาห์+วัน › วัน+ชั่วโมง) › 2 วันสุดท้ายเป็นนาฬิกาเดินทีละวินาที
มีช่องภาพรวม เดือน › สัปดาห์ › วัน › ชั่วโมง › นาที (ชุดเดียวกับตัวเลขใหญ่) และแถบความคืบหน้า · หน้าวันนี้มีแถบงานที่ใกล้ที่สุด
เลือกนักเรียนแบบติ๊ก (ค้นชื่อ · กรองตามสถานที่/มีตาราง/ที่เลือกแล้ว · เลือก/เอาออกทั้งหมดที่เห็น) บันทึกทันที ถอนออกได้ตลอดแม้งานผ่านไปแล้ว
แต่ละคนบอก "เรียนอีกกี่ครั้งก่อนวันงาน" = คาบที่ลงไว้ (รอยืนยัน/มาเรียน ที่ยังไม่ถึงเวลา) + ตารางประจำที่ยังไม่ได้ลง
(ข้ามวันหยุด/วันที่กดข้าม · วันงานนับเฉพาะคาบก่อนเวลางาน) ไม่มีตาราง = ประมาณจากที่มาเรียน 8 สัปดาห์ล่าสุด (≈)

## แอปที่สาม: อัดโชว์ — อัดวิดีโอทั้งโชว์ เก็บขึ้น Google Drive แบบเรียลไทม์

**ที่อยู่:** https://potagomo.github.io/T/show/

กดอัดครั้งเดียวทั้งโชว์ มาร์กชื่อเพลงระหว่างเล่น แล้วตัดเป็นคลิปทีละเพลง (ตัวแอปจากไฟล์ `at-show`)
ส่วนที่เพิ่มคือ **ส่งวิดีโอขึ้น Google Drive ของคุณเองตามไประหว่างอัด** เครื่องพัง แบตหมด หรือพื้นที่เต็ม วิดีโอก็ไม่หาย

**ติดตั้งเป็นแอป** — เปิดลิงก์ด้วย **Chrome** → การ์ด "ติดตั้งเป็นแอป" บนหน้าแรก หรือเมนู ⋮ → **ติดตั้งแอป**
ได้ไอคอน "อัดโชว์" ของตัวเอง เปิดเต็มจอ ใช้ได้แม้ไม่มีเน็ต (Drive ส่งต่อเองเมื่อเน็ตกลับมา) และขอพื้นที่ถาวรให้ เบราว์เซอร์จะไม่ลบวิดีโอทิ้งเอง
มีรุ่นใหม่ แอปขึ้นแถบให้กดอัปเดตเอง และไม่รีโหลดระหว่างอัด · ใช้ Chrome ดีที่สุด (Samsung Internet บางเครื่องต้องอัดผ่านตัวช่วย การ์ดมีปุ่มเปิดใน Chrome)

ของที่แอปเคยโหลดจากข้างนอก เก็บไว้ในแอปแล้ว (ตรึงรุ่น ไม่เปลี่ยนเอง):
ฟอนต์ Chakra Petch (OFL) → `show/fonts/` · ตัวอ่านนิ้ว MediaPipe tasks-vision 0.10.14 (Apache-2.0, ตรวจ sha512 กับ npm แล้ว)
และโมเดลมือ → `show/vendor/mediapipe/` (ดู `NOTICE.txt`) · ตัวอ่านนิ้วเก็บสำเนาตอนใช้ครั้งแรก ครั้งต่อไปใช้ได้แม้ไม่มีเน็ต
ไอคอนสร้างจาก `tools/make-show-icons.py` · Service Worker อยู่ที่ `show/sw.js`

**พื้นที่ในเครื่อง** — Chrome ให้พื้นที่ตามที่ว่างในเครื่อง หลังจบโชว์ พอหน้ารายละเอียดขึ้น "ครบแล้ว" ให้ลบออกจากแอป
หรือเปิดตัวเลือกในหน้าตั้งค่า Drive: **พื้นที่ใกล้เต็ม ลบโชว์เก่าที่อยู่บน Drive ครบแล้วออกจากเครื่องให้เอง**
(ลบทีละโชว์ เก่าสุดก่อน ไม่แตะโชว์ที่กำลังอัด ที่เปิดดูอยู่ หรือที่ยังส่งไม่ครบ)

**ตั้งค่าครั้งเดียว** (ฟรี ไม่ผูกบัตร) — ในแอปแตะ **ตั้งค่า Google Drive** แล้วทำตามขั้นบนจอ:
console.cloud.google.com → สร้างโปรเจกต์ → เปิด **Google Drive API** → Google Auth Platform ตั้งเป็น External
ใส่ Gmail ตัวเองใน Test users → สร้าง Client แบบ **Web application** ใส่ origin `https://potagomo.github.io`
→ วาง Client ID ในแอป → **เชื่อมต่อ Google Drive**
(ถ้าอยากให้ทุกเครื่องไม่ต้องวางเอง ใส่ Client ID ไว้ที่ `DEFAULT_CLIENT_ID` ใน `tools/show-layer/10-drive-sync.js` — Client ID ไม่ใช่ความลับ)

**ได้อะไรบน Drive** — ทุกอย่างอยู่ในโฟลเดอร์ `อัดโชว์`

| ไฟล์ | เมื่อไหร่ |
|---|---|
| `ชื่อโชว์-วันที่.mp4` | ส่งตามไปทีละ 4–32 MB ระหว่างอัด ขึ้นเป็นไฟล์ให้เห็นตอนกดหยุด · คำอธิบายไฟล์มีรายชื่อเพลงพร้อมเวลา |
| `ชื่อโชว์-วันที่.json` | ชื่อโชว์ มาร์กเพลง ไฮไลต์ เวลา — แก้ในแอปเมื่อไหร่ก็ตามไป |
| `เซ็ตลิสต์.json` | เซ็ตลิสต์ ซิงค์ระหว่างเครื่องที่ใช้ Drive บัญชีเดียวกัน |

* เน็ตหลุด ปิดแอป รีโหลด หรือแอปอัดต่อเป็น "ส่วนที่ 2" — ส่งต่อจากไบต์ที่ค้างเอง ไม่ซ้ำไม่ขาด
* เน็ตช้ากว่าค่าภาพ (1080p ราว 10 Mbps ขาขึ้น) ก็อัดได้ปกติ แค่ส่งตามไม่ทัน แล้วส่งต่อหลังจบโชว์ จอกล้องบอก "Drive ทัน / ค้าง … MB"
* เลือกได้ว่าไม่ส่งวิดีโอผ่านเน็ตมือถือ (รอ Wi-Fi) หรือส่งแค่รายชื่อเพลง ไม่ส่งวิดีโอ
* หน้ารายละเอียดของแต่ละโชว์บอกว่าส่งครบหรือยัง ครบแล้วลบออกจากแอปเพื่อคืนพื้นที่ได้ไม่ต้องกลัวหาย
* แอปเห็นเฉพาะไฟล์ที่ตัวเองสร้าง (สิทธิ์ `drive.file`) ไม่เห็นไฟล์อื่นใน Drive

**ข้อจำกัดที่ต้องรู้** — Google ให้บัตรผ่านอยู่ได้ 1 ชั่วโมง และต่ออายุได้เฉพาะตอนแตะเอง
แอปต่ออายุให้ตอนแตะ **เปิดกล้อง** และเปิดช่องส่งวิดีโอไว้ตั้งแต่เริ่มอัด วิดีโอจึงส่งต่อได้แม้โชว์ยาวเกินชั่วโมง
แต่ของที่ต้องใช้บัตรใหม่ (อัปเดต .json ตั้งชื่อไฟล์ ส่วนต่อที่เกิดหลังชั่วโมงแรก) จะรอจนกด **เชื่อมต่อ** บนหน้าแรกหรือหน้ารายละเอียด
แอปไม่เด้งหน้าล็อกอินระหว่างอัดเด็ดขาด เพราะหน้าแอปจะหลุดไปข้างหลังแล้วกล้องอาจดับ
วิดีโอบน Drive เป็นไฟล์ดิบทั้งโชว์ — คลิปแยกเพลงยังตัดจากในแอปเหมือนเดิม

**อัปเดตแอปรุ่นใหม่:**

```bash
python3 tools/update-show.py ~/Downloads/at-show-10.html   # ไฟล์ดิบไป upstream/at-show.html ผลลัพธ์ไป show/
npm i playwright && node tools/smoke-test-show.js           # ตรวจกับ Drive จำลอง: ส่งระหว่างอัด Drive ล่ม บัตรหมดอายุ รีโหลดกลางโชว์
```

**อัดแล้วถูกตัดเป็นส่วนทุก 25 วินาที** (บันทึกเหตุขัดข้องขึ้น `no data for 25s`) — กล้องเครื่องนั้นไม่ส่งข้อมูลระหว่างอัด
เจอจริงบน Samsung Internet 30: อัดจากกล้องตรง ๆ ไม่ปล่อยข้อมูลจนปิดไฟล์ทุกชนิดไฟล์ แต่ถ้าวาดภาพลง canvas ก่อนแล้วอัดจาก canvas ได้ปกติ
แอปจึงมีโหมด **อัดผ่านตัวช่วย** (`tools/show-layer/30-relay.js`) ที่เปิดเองเมื่อเจออาการนี้ครั้งแรก ส่วนถัดไปจะอัดต่อเนื่อง
และ MP4 ยังแบ่งท่อน ตัดแยกเพลงได้ · ปิด/เปิดเองได้ที่หน้ากล้อง → ตั้งค่า → ภาพและเสียง
ปุ่ม **ตรวจว่ากล้องส่งข้อมูลต่อเนื่องไหม** ในหน้าเดียวกันลองอัดสั้น ๆ 13 แบบ (ชนิดไฟล์ 30 เฟรม canvas WebCodecs) แล้วบอกว่าแบบไหนใช้ได้
(`tools/show-layer/20-device-check.js`)

ส่วนเสริมอยู่ใน `tools/show-layer/` — แก้ที่นั่นแล้วรัน `update-show.py` อย่าแก้ `show/index.html` ตรง ๆ

## แถบล่างแบบย่อ · แผงเขียนโน้ตลอย · ลากตั้งวนซ้ำ (กลอง → MIDI)

**ย่อแถบล่าง** (ปุ่ม ▾ มุมแถบ) เหลือแถวเดียว: เล่น · หยุด · ⏮ · นาฬิกา — กริดสูงขึ้น
(iPad แนวนอน 418 → 708px · แนวตั้ง 689 → 1020px · มือถือ 337 → 718px) แอปจำไว้ว่าย่ออยู่

การวาง (แนวก้าน) · ปุ่ม ▤ ดูทุกหมวดพร้อมกัน · ลากหัวแผงไปไว้ตรงไหนของจอก็ได้
· ⏱ ตั้งให้ซ่อนเองเมื่อไม่ได้แตะ 3–30 วิ (หรือไม่ซ่อน) แล้วจะเหลือปุ่มกลมตรงที่เดิม บอกค่าโน้ตที่เลือกอยู่
แตะเพื่อเรียกแผงกลับ ลากเพื่อย้าย · ปุ่ม – ซ่อนทันที
· **ท้ายแผงมีแถบห้องเสมอ** ไม่ว่าอยู่หมวดไหน: คัดลอกห้องนี้ · วางลงห้องนี้ · ซ้ำห้องก่อนหน้า (ห้อง = ห้องที่หัวอ่านอยู่)
บรรทัดบนปุ่มบอก "หัวอ่านอยู่ห้อง 3 · คัดลอกไว้: ห้อง 1 (8 ตัวโน้ต)" และขึ้นผลทันทีที่กด
**ตั้งวนซ้ำ**: ลากคลุมบนแถบไม้บรรทัดใต้แถบเลขห้อง (มีขีดห้อง/จังหวะ/ช่องย่อยให้กะ) ระหว่างลากมีป้ายบอก
"ห้อง 2 จังหวะ 1 → ห้อง 4 จังหวะ 1 · 8 จังหวะ" · ลากขอบเพื่อปรับ · แตะในช่วงเพื่อยกเลิก · ย้อน/ถัดไป เลื่อนทั้งช่วง
smoke-test ตรวจทั้งสามอย่าง (แถบเตี้ยลงจริง · ปุ่มในแผงเลือกค่าโน้ตได้ · เล่นแล้วไม่หลุดช่วงวนซ้ำ · แตะยกเลิกได้)
**ช่องชื่อแถว** กว้างขึ้นบน iPad ชื่อเต็มทุกแถว (ไฮแฮตเปิด/ปิด/เท้า แยกออก) · มือถือใช้ชื่อย่อ (แฮตเปิด แฮตปิด แฮตเท้า เบล …)

## 1. เปิดใช้ GitHub Pages (ทำครั้งเดียว)

ไปที่ **Settings → Pages** ของ repo นี้ แล้วเลือกอย่างใดอย่างหนึ่ง

**แบบที่แนะนำ — GitHub Actions**

* Build and deployment → Source = **GitHub Actions**
* จากนั้นทุกครั้งที่ push จะ deploy ให้เองด้วย `.github/workflows/pages.yml`
  ซึ่งจะประทับเลข commit ลงใน `sw.js` และตรวจว่าไฟล์ที่จำเป็นครบก่อนเผยแพร่

> ขั้นตอนนี้ต้องกดเองครั้งเดียว ให้ workflow ทำแทนไม่ได้ —
> GITHUB_TOKEN ของ Actions ไม่มีสิทธิ์สร้าง Pages site ครั้งแรก
> (ลองแล้วได้ `Create Pages site failed: Resource not accessible by integration`)
> พอเปิดเสร็จ สั่ง re-run ที่หน้า Actions หรือ push อะไรก็ได้อีกครั้ง แล้วจะ deploy ผ่าน

**แบบง่าย — Deploy from a branch**

* Source = **Deploy from a branch**
* Branch = `claude/web-app-html-file-bicwtc` (หรือ `main`) · Folder = **/ (root)**
* ใช้ได้เหมือนกัน แค่ไม่มีขั้นตอนตรวจไฟล์ให้

## 3. งานที่บันทึกเก็บอยู่ที่ไหน — อ่านตรงนี้ก่อน

งานเก็บอยู่ใน `localStorage` ของเบราว์เซอร์ **บนเครื่องนั้นเครื่องเดียว**
ไม่ได้ซิงก์ข้ามเครื่อง และไม่มีสำเนาอยู่บนเซิร์ฟเวอร์

**สามข้อที่ต้องรู้**

1. **ของเดิมที่เคยทำไว้ตอนเปิดจากไฟล์ในเครื่อง จะไม่ตามมาเอง**
   เพราะเบราว์เซอร์มองว่า `file://` กับ `https://` เป็นคนละที่เก็บ
   ให้เปิดไฟล์เดิม → กด **ดาวน์โหลดไฟล์สำรอง (.klong)** → เปิดเว็บแอป → **นำเข้าไฟล์สำรอง**

2. **iOS ล้างข้อมูลเว็บทิ้งได้เอง** ถ้าไม่ได้เปิดแอปนานหลายสัปดาห์
   การติดตั้งลงหน้าโฮมช่วยได้มาก แต่ไม่รับประกัน

3. เพราะสองข้อบน → **ไฟล์สำรอง `.klong` คือของจริง** จุดบันทึกในเครื่องเป็นแค่ความสะดวก
   งานไหนสำคัญ ดาวน์โหลด `.klong` เก็บไว้ใน iCloud Drive หรือ Google Drive ด้วย

## 4. เรื่องความปลอดภัย

**ที่ทำให้แล้ว**

* **HTTPS** ทุกการเชื่อมต่อ GitHub Pages บังคับให้อยู่แล้ว
* **ไม่ต่อออกไปไหนเลย** ไม่มี CDN ไม่มีตัวเก็บสถิติ ไม่มีโฆษณา
  ฟอนต์ IBM Plex Sans Thai ถูกย้ายมาเก็บไว้ในโปรเจกต์เอง (สัญญาอนุญาต SIL OFL 1.1)
  จึงไม่มีการเรียก Google Fonts อีกแล้ว — ทั้งเร็วขึ้น เปิดออฟไลน์ได้ และไม่มีใครนอกเครื่องรู้ว่าเราเปิดหน้านี้
* **Content-Security-Policy** ล็อกไว้ว่าหน้านี้โหลดโค้ด รูป ฟอนต์ และเสียงได้จากตัวเองเท่านั้น
  ต่อให้มีใครแทรกลิงก์แปลกปลอมเข้ามา เบราว์เซอร์ก็จะไม่ยอมโหลด
* **กันการเอาหน้านี้ไปฝังใน iframe ของเว็บอื่น** (clickjacking)
* **สั่งไม่ให้เสิร์ชเอนจินเก็บไปทำดัชนี** ด้วย `<meta name="robots" content="noindex">`

**ที่ต้องรู้ไว้**

* repo นี้เป็น **public** ฉะนั้น **ใครที่รู้ลิงก์ก็เปิดเว็บแอปได้** ตัวโปรแกรมเป็นสาธารณะ
* แต่ **งานของแต่ละคนอยู่แค่ในเครื่องของคนนั้น** คนอื่นเปิดลิงก์เดียวกันจะเห็นกริดเปล่า
  ไม่มีทางเห็นงานของเรา เพราะไม่มีอะไรถูกส่งขึ้นไปเก็บไว้ตรงกลางเลย
* ถ้าอยากไม่ให้คนนอกเปิดเว็บแอปได้เลยจริง ๆ GitHub Pages แบบฟรีทำไม่ได้
  ต้องใช้ Cloudflare Access วางหน้าไว้ หรือเปลี่ยนไปใช้ GitHub Pages ของ repo private (ต้องมีแพ็กเกจเสียเงิน)
* `'unsafe-eval'` ใน CSP จำเป็นจริง ๆ เพราะตัวโปรแกรมถูกเก็บเป็นข้อความแล้วรันด้วย `new Function()`
  ซึ่งเป็นกลไกของฟีเจอร์ "ไฟล์ล็อก" ที่มีมาแต่เดิม ไม่ได้เพิ่งใส่เพิ่ม

## 5. ฟรีตลอดไปแค่ไหน

GitHub Pages สำหรับ repo สาธารณะ **ฟรี ไม่มีวันหมดอายุ ไม่ต้องผูกบัตร**
ไม่มีการ "หลับ" แบบบริการโฮสต์ฟรีเจ้าอื่น และไม่มีโควตาที่ใช้แล้วหมด

ขีดจำกัดที่ GitHub ประกาศไว้ — ของเราอยู่ห่างมาก

| รายการ | ขีดจำกัด | โปรเจกต์นี้ใช้ |
|---|---|---|
| ขนาดเว็บ | 1 GB | ~0.4 MB |
| ปริมาณโหลดต่อเดือน | 100 GB | ไม่ถึง แม้เปิดวันละหลายร้อยครั้ง |
| จำนวน build ต่อชั่วโมง | 10 | เท่าจำนวนครั้งที่ push |

แถมยังเป็นเว็บนิ่ง (static) ล้วน ไม่มีเซิร์ฟเวอร์ ไม่มีฐานข้อมูล ไม่มี dependency
ที่ต้องคอยอัปเดตตามช่องโหว่ จึงไม่มีอะไรพังเองตามเวลา
และถึงวันหนึ่งอยากย้ายไปโฮสต์ที่อื่น ก็แค่ก๊อบไฟล์ทั้งโฟลเดอร์ไปวาง ใช้ได้ทันที

## 6. อัปเดตเมื่อมีไฟล์ HTML รุ่นใหม่

`index.html` ที่ deploy อยู่ = **ไฟล์ต้นฉบับ + ชั้นเว็บแอป + งาน UI ที่แก้ไว้ใน repo**
มีของสามชั้นปนกันอยู่ ฉะนั้นพอได้ไฟล์รุ่นใหม่มา **ห้ามเขียนทับ** — ต้องรวมเข้าหากัน

```bash
# 1) รวมรุ่นใหม่เข้ากับของเดิม
python3 tools/merge-upstream.py ~/Downloads/klong-pro-9.html

# 2) ตรวจด้วยเบราว์เซอร์จริง
npm i playwright && node tools/smoke-test.js

# 3) ผ่านแล้วค่อยขึ้น
git add -A && git commit -m "รวมรุ่น 9" && git push
```

### มันทำงานยังไง

`upstream/klong-pro.html` เก็บไฟล์ดิบ**รุ่นล่าสุดที่รวมไปแล้ว** ไว้เป็นจุดอ้างอิง
git จึงเทียบได้สามทางว่า "รุ่นก่อนเป็นแบบนี้ · เราแก้เป็นแบบนี้ · ผู้พัฒนาแก้เป็นแบบนั้น"

* แก้คนละที่ → **รวมให้เองทั้งคู่** ไม่ต้องทำอะไร
* แก้ทับที่เดียวกัน → **หยุดและเตือน** พร้อมโชว์ทั้งสองเวอร์ชันให้เลือก
  ไฟล์ที่มีเครื่องหมายชนจะถูกเขียนไว้ที่ `index.html.merge-conflict`
  ส่วน `index.html` ตัวจริงไม่ถูกแตะจนกว่าจะแก้เสร็จ

ทดสอบแล้วว่าใช้ได้จริง: ให้รุ่นใหม่เพิ่มปุ่ม เพิ่ม CSS และเปลี่ยน `--rowh`
พร้อมกับที่ฝั่งเราขยายปุ่มให้กดง่ายขึ้น ผลคือ**ได้ครบทั้งสองฝั่ง**และชั้นเว็บแอปไม่หาย

### ด่านที่ merge-upstream.py ไม่ยอมให้ผ่าน

ทุกด่านคืน exit 1 และ **ไม่แตะ `index.html` เลย**

| เจออะไร | ทำไมถึงกั้น |
|---|---|
| ไฟล์ใหม่**เพิ่ม**ลิงก์ของจากข้างนอก (CDN) | CSP จะบล็อกเงียบ ๆ ไม่มี error ให้เห็น · เทียบกับรุ่นก่อน ไม่ได้จับ Google Fonts ที่ติดมาเป็นของเดิม |
| ชนกัน | ทั้งสองฝั่งแก้ที่เดียวกัน ต้องให้คนตัดสิน |
| รวมแล้วชั้นเว็บแอปหายบางส่วน | มีอะไรผิดปกติ ต้องดูด้วยมือ |
| ส่งไฟล์ที่มีชั้นเว็บแอปอยู่แล้ว | ใช้ผิดสคริปต์ — ไฟล์แบบนั้นเอาไปทับ `index.html` ได้เลย |
| ส่งไฟล์เดิมซ้ำ | ไม่มีอะไรต้องทำ |

### ทางที่ลื่นกว่า: พัฒนาต่อจาก index.html ไปเลย

ถ้าพัฒนาต่อจากไฟล์เดิมของตัวเองเรื่อย ๆ สองสายจะห่างกันขึ้นทุกรอบ
และวันหนึ่งที่ไปรื้อ CSS ส่วนที่ repo ก็แก้ไว้ conflict จะเริ่มเยอะ

แก้ง่ายมาก: **โหลด `index.html` จาก repo ไปพัฒนาต่อ แล้วส่งกลับมา** เหลือสายเดียว
conflict แทบไม่เกิด ชั้นเว็บแอปในไฟล์มีคอมเมนต์กำกับชัดและอยู่ริม ๆ ไฟล์ ไม่เกะกะ
กรณีนี้ไม่ต้องใช้ `merge-upstream.py` เลย เอาไฟล์ทับ `index.html` แล้ว commit ได้เลย
(สคริปต์จะบอกเองถ้าเผลอส่งไฟล์แบบนี้มา)

### ส่วน apply-webapp-layer.py ยังอยู่ไหม

ยังอยู่ แต่ใช้เฉพาะตอน**เริ่มใหม่จากศูนย์** เท่านั้น เช่นอยากทิ้งงาน UI ทั้งหมด
แล้วตั้งต้นจากไฟล์ดิบใหม่ ทางปกติคือ `merge-upstream.py`
ด่านสแกนของจากข้างนอกอยู่ใน `tools/_layer.py` ที่ทั้งสองสคริปต์ใช้ร่วมกัน

### ฝั่งผู้ใช้

จะไม่ถูกรีโหลดกลางคัน — พอมีรุ่นใหม่จะมี **แถบขึ้นข้างบนให้กดอัปเดตเอง**
ตั้งใจทำแบบนี้เพราะถ้ารีโหลดเองอัตโนมัติ งานที่กำลังแก้อยู่บนกริดจะหายไป

## 8. ทดสอบอะไรไปแล้วบ้าง

รันจริงบน Chromium ทั้งขนาดจอ iPad Pro 11" และ iPhone 13 ผ่านทุกข้อ

* โปรแกรมเปิดขึ้นและวาดกริดได้ทั้งสองขนาดจอ
* แตะนิ้ววางโน้ตบนกริดได้ แล้วส่งออกได้จริงทั้ง `.mid` (ขึ้นต้นด้วย `MThd` ถูกต้อง) และ `.musicxml`
* กดเล่นแล้วหัวอ่านเดินและมีเสียงออก (AudioContext ทำงาน)
* **ตัดเน็ตแล้วโหลดใหม่ ยังเปิดใช้ได้ครบ ฟอนต์มาครบ**
* ไม่มีคำขอออกไปนอกเครื่องแม้แต่รายการเดียว
* ไม่มี CSP violation และไม่มี error ใน console
* บันทึก/อ่าน/ลบจุดบันทึกในเครื่องทำงานปกติ
* แถบแจ้งรุ่นใหม่ไม่ขึ้นตอนเปิดครั้งแรก ขึ้นเมื่อมีรุ่นใหม่จริง และกดแล้วอัปเดตเรียบร้อย

### ธีมที่ใช้อยู่

มิดเซนจูรี่ (แถบไม้วอลนัท ขอบทองเหลือง ปุ่มกดลงได้จริง) มีโหมดกลางวันและกลางคืน
สลับได้ที่แถบล่างหัวข้อ "แสงหน้าจอ" ค่าเริ่มต้นตามที่ตั้งไว้ในเครื่อง ไฟล์อยู่ใน `theme/`
ถ้ารับรุ่นใหม่แล้วชุดทดสอบฟ้องสีหลุดธีม ดูวิธีแก้ใน `drum-pro-ui` ข้อ 0.5

`drum-pro-ui` เก็บสิ่งที่คลังทั่วไปไม่มีทางรู้:

* **ลำดับการทำงาน** — วิเคราะห์ UX ปัจจุบัน ระบุปัญหาพร้อมหลักฐาน จัดลำดับข้อมูล
  เสนอ design system และโครง component ให้ผู้ใช้เห็นชอบ **แล้วจึงลงมือแก้**
* **กับดักของ repo นี้** — `index.html` เป็นไฟล์ที่ถูกสร้างขึ้น แก้ UI ลงไปตรง ๆ
  แล้วงานจะหายตอนรับไฟล์ต้นฉบับรุ่นใหม่ จึงต้องตกลงก่อนว่าจะเก็บงาน UI ไว้ที่ไหน
* **ข้อเท็จจริงของโปรแกรม** — design token ที่มีอยู่, ผัง component (`references/ui-map.md`),
  พฤติกรรมของกริดกับ playhead, ข้อห้ามเรื่อง CSP และที่อยู่ของมาตรฐานโน้ตกลองในโค้ด
  (`const STAFF` / `headOf()`) ซึ่งเป็นแหล่งอ้างอิง ห้ามเดาจากความจำ

## 10. เสียงกลองจริง

เสียงตอนเล่นกลองที่ถอดเป็นเสียงที่อัดจากกลองจริงแล้ว (เดิมเป็นเสียงสังเคราะห์)
เลือกชุดได้ที่แผงตั้งค่า ส่วน **การฟัง → ชุดเสียงกลอง**: อะคูสติก (ค่าเริ่มต้น) · ร็อก · ป๊อป · แจ๊ส · ฮิปฮอป · สังเคราะห์ (สร้างในเครื่อง ไม่ต้องโหลด)

* โหลดเฉพาะชุดที่เลือก (0.7-4.4 MB) ครั้งเดียว แล้วเก็บในเครื่อง ใช้ออฟไลน์ได้ อัปเดตโปรแกรมแล้วไม่ต้องโหลดใหม่
* น้ำหนักการตีเลือกเสียง เบา/ปกติ/เน้น จากการตีจริงคนละครั้ง สุ่มไม่ซ้ำ ไฮแฮตเปิดถูกตัดเมื่อเหยียบ
* ระหว่างที่ชุดยังโหลดไม่เสร็จ หรือท่าที่ไม่มีไฟล์ (ครอสสติ๊ก) ใช้ชุดสังเคราะห์ในเครื่อง ไม่มีวันเงียบ
* ชุดอะคูสติกเป็นของ **Salamander Drumkit by Alexander Holm (CC BY-SA 3.0)** — แสดงเครดิตใต้ปุ่มเลือกชุด
  ชุดอื่นเป็น CC0 รายละเอียดใน `sounds/LICENSES.txt`

รายละเอียดสำหรับคนแก้โค้ดอยู่ใน `sounds/README.md`

* ขนาดโน้ต: ขนาดบรรทัด 5 เส้น 5–11 มม. (Staff size) · ห้องต่อบรรทัด 1–8 หรืออัตโนมัติ (ใส่จนเต็มบรรทัด) ·
  ความแน่นของโน้ต · ระยะห่างระหว่างบรรทัด · ย่อหน้าบรรทัดแรก · จัดบรรทัดให้เต็มหน้า · ยืดบรรทัดสุดท้าย
* หัวกระดาษ: ชื่อเพลง (ขนาด pt) · คำบรรยาย · ข้อความมุมซ้าย · ศิลปิน/ผู้แต่ง · ถอดโน้ตโดย · ข้อความท้ายหน้าแรก · ชื่อเพลงบนหน้าถัดไป
* เครื่องหมาย: เลขห้อง (ต้นบรรทัด · ทุกห้อง · ทุก 5 · ทุก 10 · ไม่แสดง) · เลขหน้า (กลางล่าง · มุมขวาล่าง · มุมบนด้านนอก · ไม่แสดง)
  · ป้ายความเร็ว · คีย์กลอง · ดำบนขาว/สีตามกลอง

## 12. มือถือ + ปากกา (Android · Galaxy S Pen)

เว็บเดียวกันทุกเครื่อง ไม่มีแอปแยก — มือถือ Android เปิดลิงก์ด้วย Chrome แล้วกด **ติดตั้งแอป** ในการ์ด "ติดตั้งลงมือถือ" บนหน้าแรก
Chrome สร้างแอปจริงให้ (WebAPK): ไอคอน Klong Pro ในหน้าจอและลิ้นชักแอป เปิดเต็มจอ ใช้ได้ไม่มีเน็ต อัปเดตเองตามเว็บ
และใช้ที่เก็บงานชุดเดียวกับใน Chrome · การ์ดนี้ (`klong-theme.js`) ใช้คำเชิญติดตั้งของเบราว์เซอร์ (`beforeinstallprompt`)
ถ้าเบราว์เซอร์ไม่มีคำเชิญ (Safari, Samsung Internet บางรุ่น) บอกวิธีกดเองแทน · ไม่ขึ้นเมื่อเปิดเป็นแอปอยู่แล้ว
`manifest.webmanifest` ชื่อแอป Klong Pro และมีภาพหน้าจอ (`icons/shot-*.jpg`) ให้หน้าติดตั้งของ Chrome

**จอมือถือจัดหน้าใหม่ให้กริดได้พื้นที่** (จอแคบ ≤599px หรือแนวนอนที่เตี้ย ≤500px — iPad ไม่เปลี่ยน):
* แถบบนแถวเดียว: ↶ ย้อนแก้ · เครื่องมือ (เลื่อน วาง เลือก ลบ น้ำหนัก) · **⋯** = นำเข้าไฟล์ ส่งออก ตั้งค่า โหมด
* แผงเขียนโน้ตเกาะขอบจอแทนการลอยทับกริด — แนวตั้งอยู่ใต้กริด หมวดละแถวเดียว (ค่าโน้ต น้ำหนัก ลูกเล่น การวาง **ห้อง**)
  แนวนอนอยู่คอลัมน์ขวา และปุ่มเล่น/หยุด/นาฬิกาขึ้นไปอยู่บนแถบบน
* ผลการกด (คัดลอกห้อง นำเข้าไฟล์ ข้อผิดพลาด) ขึ้นเป็นป้ายลอยใต้แถบบน 3 วินาที
* กริดแนวตั้ง 67% ของจอ (เดิม 40%) · แนวนอนเห็นแถวกลองแล้ว (เดิมเห็นแค่ไม้บรรทัด)

**ปากกา (S Pen และปากกาทุกแบบ):** วางโน้ตได้ทุกเครื่องมือ นิ้วใช้เลื่อนจอ (แบบเดียวกับ Apple Pencil บน iPad)
* ลอยปากกาเหนือจอ = เห็นจุดจาง ๆ ตรงที่จะวาง · วงแดง = แตะแล้วจะลบตัวเดิม
* **กดปุ่มข้างปากกาค้างแล้วแตะ/ลาก = ลบโน้ต** ไม่ต้องสลับเครื่องมือ
* สั่นเบา ๆ ทุกครั้งที่ปากกาวาง/ลบโน้ต (Android · iPad ไม่มีระบบสั่นให้เว็บ)

**ปัดย้อนกลับของ Android** ถอยทีละหน้า: ปิดแผงตั้งค่า → ออกจากหน้าส่งออก → กลับหน้าแรก (เก็บงานค้างไว้ก่อน) แทนการปิดแอปทิ้ง

แก้บั๊ก: แอปที่ติดตั้งบน Android เคยมีแถบว่างด้านบนและแถวนาฬิกาหลุดใต้ขอบจอ (โค้ดแก้ขอบจอ iPad ไปทำงานผิดเครื่อง)
ตรวจ: `node tools/smoke-test.js` ชุด **Android** (384×784 และหมุนเป็น 784×352 · ปากกาจำลองผ่าน CDP)

## 13. เขียนระหว่างเล่น · ช่องแรกของกริด · แถบเสียงตอนย่อ

* **วาง/ลบ/แก้โน้ตระหว่างเล่น มีผลทันที** — วนซ้ำห้องเดิมแล้ววางโน้ต รอบถัดไปดังเลย ไม่ต้องหยุดแล้วกดเล่นใหม่
  (`afterEdit()` ตั้งธง `evDirty` · `pump()` สร้างรายการเสียงใหม่ต่อจากจุดที่ตั้งเวลาไปแล้ว `schedHorizon` ไม่ดังซ้ำ)
* **ช่องแรกของกริดเว้นห่างช่องชื่อแถว 28px** (`GRID_LEAD` ใน `X0`/`T0`) — เดิมจังหวะแรกห่างปุ่ม S แค่ ~6px แตะแล้วโดนปุ่ม
  แตะในช่องว่างนี้ = ช่องแรก · แตะเยื้องตัวเดิมแต่ตกช่องเดียวกัน = ตัวเดิม (ลบ/เลือก) ไม่วางซ้อน (`noteAtTap`)
* **แถบเสียงเพลง/กลองตอนย่อแถบล่าง** (`#tpMix` ในแถวเล่น) — สำเนาของแถบในแถวล่างสุดที่ซ่อนตอนย่อ ขยับตามกันสองทาง
  มือถือแถวเล่นไม่มีที่ จึงอยู่ในหมวด **เสียง** ของแผงเขียนโน้ต
ตรวจ: `node tools/smoke-test.js` ชุด **iPad-แก้ระหว่างเล่น**
